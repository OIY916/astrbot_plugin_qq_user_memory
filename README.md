# astrbot_plugin_qq_user_memory

> 跨群用户记忆 —— 以 **QQ 号**为主键，记住每个人说过什么，换个群也认得出来。

AstrBot 插件。纯标准库实现，**零第三方依赖**，只用 SQLite。

## 更新日志

### v1.1.0 (2026-11-01)

**可视 WebUI + 注入质量优化**

- 🖥️ **新增 WebUI 管理页面**
  在 AstrBot WebUI 的插件页里直接浏览记忆：用户列表、单人档案、好感度排行、
  群组分布、全文检索。纯新增，**不影响 QQ 侧的原有逻辑**。
  - 后端 `webui_api.py`（6 个只读接口）
  - 前端 `pages/app/`（`index.html` / `script.js` / `style.css`）
- ✨ **新增 `display_name: 跨群用户记忆`**
  插件在 WebUI 里显示为中文名，不再是目录名。
- 🔧 **注入重排，画像不再被截断**
  原实现把「活跃群全列表」排在【画像】之前，实测 300 字符里它一项就占 140（47%），
  导致**画像经常整段被截掉**（12 个活跃用户里 9 个中招）。
  新顺序：好感度 → 画像 → 事实 → 头部 → 跨群发言 → 「还在 N 个其他群活跃」一句话。
- 🐛 **修复：单群用户拿不到画像**
  原代码在「跨群发言 < 2 条」时走快捷路径，**只返回好感度一行**。
  而画像恰恰最体现「认识这个人」，跨不跨群不该影响要不要认识他。已补上。
- 🔧 **`min_messages_before_inject` 默认值 3 → 20**
  3 条发言生成的画像质量不靠谱，提到 20 过滤噪声。
- 🧹 **删除「禁用称呼」输出过滤功能**
  该功能只针对特定群的私人场景，对通用使用者无意义，相关代码/配置/文档一并移除。
- 🗂️ `support_platforms` 修正为列表格式（原为字符串，框架会当作空列表而失效）

### v1.0.1 (2026-10-24)

**画像时间精确到分钟 + 好感度手动锁定**

- 🕐 **新增 `profile_time` 配置**（`"HH:MM"`，默认 `00:00` 午夜）
  取代原来只支持整点的 `profile_hour`。旧配置保留为回退，从 v1.0.0 升级无需改动。
- 💬 **新增 `/记忆 画像时间` 指令**
  不填参数 = 查看当前时间；填 `HH:MM` = 修改（管理员）。
  改完**立即重排定时任务，无需重启或重载插件**。
- 🔒 **好感度支持手动锁定**
  `/记忆 好感 <QQ号> <分数>` 设定后该条被锁定，之后的每日自动评估**不再改动它**。
  解除锁定用 `/记忆 解锁好感 <QQ号>`。
  适合「把某人固定在最亲/最烦的档位」这种需求。
- 🗄️ **数据库 schema 升级 v3 → v4**
  新增 `affinity.locked` 列，含自动迁移（`ALTER TABLE`），旧库无损升级。
- 🧼 **代码零硬编码**
  `affinity_viewer_qq` 改为配置驱动，代码里不再出现任何个人 QQ 号或名字。

### v1.0.0 (2026-10-23)

🎉 **初始版本发布**

- 跨群聚合：以 QQ 号为主键，同一个 QQ 在不同群的发言合并成一份档案

## 它解决什么问题

普通的群聊机器人换个群就"失忆"了：在 A 群认识你，在 B 群当陌生人。

这个插件按 **QQ 号**聚合，同一个人在任意群的发言都归到同一份档案里。
当你 @ 机器人时，它会把"这个人在**别的群**说过什么"注入模型上下文，
于是它能跨群认出你。

---

## 特性

| 能力 | 说明 |
|---|---|
| **跨群聚合** | 同一个 QQ 在多个群的发言合并成一个人的档案 |
| **中文全文检索** | SQLite FTS5 + 中文逐字切分，搜"钓鱼"能命中"我去钓鱼了" |
| **每日画像** | 用 LLM 把发言归纳成 2-3 句性格描述，让它"认识"这个人 |
| **好感度系统** | 机器人对每个人的态度分数（0-100），影响配合度 |
| **懒注入** | 只注入**其他群**的内容，当前群的历史上下文里已经有了，不重复浪费 token |
| **可视 WebUI** | AstrBot 插件页里直接浏览用户档案、好感排行、群组分布、全文检索 |
| **自动清理** | 每人最多保留 N 条、超期自动过期，库不会无限膨胀 |

## 安装

1. 把整个文件夹放到 AstrBot 的插件目录：

```
data/plugins/astrbot_plugin_qq_user_memory/
```

2. 确认目录里至少有这几个文件：

```
main.py
memory_store.py
profiler.py
_conf_schema.json
metadata.yaml
```

3. 重启 AstrBot，日志里应出现：

```
[user_memory] 记忆库就绪: .../plugin_data/astrbot_plugin_qq_user_memory/user_memory.db (N 人 / M 条发言)
```

## 配置

在 AstrBot WebUI 的插件配置页调整，或直接改
`data/config/astrbot_plugin_qq_user_memory_config.json`。

**常用项：**

| 配置 | 默认 | 说明 |
|---|---|---|
| `enable` | `true` | 总开关 |
| `enabled_groups` | `[]` | 留空=所有群；填群号=只记录这些群 |
| `inject_on_all` | `false` | `false`=只在 @ 机器人时注入；`true`=读空气也注入 |
| `max_inject_chars` | `300` | 注入记忆的字数上限 |
| `max_messages_per_user` | `2000` | 每人保留多少条发言 |
| `retention_days` | `180` | 发言保留天数，`0`=永久 |
| `enable_daily_profile` | `true` | 每日自动生成画像 |
| `profile_time` | `"00:00"` | 每日画像执行时间，24 小时制 HH:MM，精确到分钟。<br>例：`02:30` / `23:45`。也可用指令 `/记忆 画像时间 02:30` 在线修改 |
| `profile_hour` | `0` | **（已弃用）** 旧版整点配置，仅在 `profile_time` 为空时作为回退 |
| `affinity_viewer_qq` | `""` | 留空=所有人可查好感度；填 QQ=只有这个人能查 |
| `min_messages_before_inject` | `20` | 至少说过几条才注入记忆（太少的话画像质量不靠谱，默认 20） |
| `recent_limit` | `3` | 注入「其他群里说过」的条数 |
| `related_limit` | `2` | 注入「和当前话题相关的旧发言」条数 |
| `facts_limit` | `6` | 注入画像/事实的条数上限 |

## WebUI

插件带一个**只读**的可视化管理页面，在 AstrBot WebUI 里直接可用：

**打开方式**：WebUI → 插件管理 → 找到「跨群用户记忆」 → 点开页面 `app`

| 页面 | 内容 |
|---|---|
| **用户列表** | 所有记住的人，可按昵称/QQ 筛选，三种排序（发言数 / 最近活跃 / 好感度） |
| **单人档案** | 画像、好感度（含 🔒 锁定标记）、活跃群、用过的昵称、最近发言 |
| **好感排行** | 好感度 Top N，含评估理由 |
| **群组分布** | 每个群的人数、发言数、最近活跃时间 |
| **全文检索** | 在全部发言里搜关键词，点昵称可直接跳转到该人档案 |

> ⚠️ 页面**必须从 Dashboard 的插件详情页进入**（它在 iframe 里嵌页面并注入 bridge SDK）。
> 直接复制 URL 打开会提示「SDK 不可用」。
>
> 当前为**只读**版本，修改/删除类操作仍走 `/记忆` 指令。

## 指令

在群里或私聊发送。所有子命令都支持别名（括号内为可替换写法）。

### 查询类（所有人可用）

```
/记忆 查 <QQ号或昵称>      看这个人的完整档案        （别名：查看 / 查询 / who）
/记忆 搜 <关键词>          全文检索所有群的发言      （别名：搜索 / 找 / search）
/记忆 统计                 库里有数据的规模          （别名：状态 / stats）
/记忆 最近                 最近记录情况              （别名：recent）
```

### 记忆管理

```
/记忆 记住 <QQ号> <内容>   手动记一条事实            （别名：记 / add）
/记忆 忘记 <QQ号>          删除某人全部记忆（管理员） （别名：删除 / forget）
```

### 画像

```
/记忆 更新画像 [QQ号]      立刻重跑画像（管理员）    （别名：画像 / profile）
                           不填 QQ 号 = 全量重跑
/记忆 画像时间             查看当前每日画像执行时间
/记忆 画像时间 <HH:MM>     修改执行时间（管理员）     （别名：时间 / profile_time）
                           例：/记忆 画像时间 02:30
                           改完立即重排定时任务，无需重启
```

### 好感度

```
/记忆 好感                 好感度排行
/记忆 好感 <QQ号>          单人好感度详情
/记忆 好感 <QQ号> <分数>   设定并锁定为指定分数      （例：/记忆 好感 123456789 0）
                           锁定后每日自动评估不再改动
/记忆 解锁好感 <QQ号>      解除锁定，恢复自动评估
```

> `好感` / `解锁好感` / `画像时间`（修改时）受 `affinity_viewer_qq` 与管理员权限限制，
> 详见下方配置说明。

## 画像与好感度需要 LLM

每日画像固定使用 **DeepSeek**（`deepseek-chat`），key 从你的 AstrBot 配置读取：

```
data/cmd_config.json → provider_sources 里 id == "deepseek" 的 key
```

所以需要先在 AstrBot 里配好 DeepSeek 供应商。
如果只想用基础记忆功能，可以关掉：

```json
{ "enable_daily_profile": false }
```

这样就不需要任何额外 API。

---

## 好感度是怎么来的

**单向**（机器人对群友），`0-100`，初始 `40`。

每天和画像一起，由 `deepseek-chat` 评估一次：根据这个人是否常夸它、骂它、
聊天是否让人觉得舒服，给出 `-20 ~ +20` 的调整。

分档影响态度：

| 分数 | 表现 |
|---|---|
| 85+ | 有求必应，肉麻要求也配合 |
| 65-85 | 愿意配合，先嘴硬两句 |
| 45-65 | 看心情，会调侃 |
| 25-45 | 敷衍、岔开话题 |
| 0-25 | 直接不配合 |

> 注意：好感度只注入给**人格提示词**，需要你在 AstrBot 的人格设定里写清楚
> "好感度如何影响态度"，模型才会照做。插件只负责提供数字。

**手动锁定**：用 `/记忆 好感 <QQ号> <分数>` 设定后，该条会被锁定，
之后的每日自动评估**不再改动它**；要恢复自动评估用 `/记忆 解锁好感 <QQ号>`。
适合「把某人固定在最亲/最烦的档位」这种需求。

## 已知限制

- **没有语义检索**：用 FTS5 关键词，不是向量。搜"钓鱼"能中，但搜"垂钓"不一定。
  （这是刻意的：DeepSeek 没有 embedding API，也不想增加成本）
- **画像需要 API**：关掉 `enable_daily_profile` 后，只有原文检索，没有性格描述。
- **中文切分是逐字**：好处是任意子串都能搜到，代价是索引比英文大一些。
- **好感度依赖人格提示词**：插件只提供数字，态度是否能体现取决于你的人格写得够不够清楚。
